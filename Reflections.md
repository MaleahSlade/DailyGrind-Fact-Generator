1. Why was it important to re-format the data from the Useless Facts API before sending it to your own client? What are the benefits of an API providing a clean, minimal response? We had to reformat it so each fun fact was easy to read on the front end. Using an API that provides simple responses minimizes the interface design we need to create to accommodate the data.  
2. In the catch block, why is it better to send a generic error message to the client instead of the actual error object from axios? The client doesn't need to see what's happening under the hood of the site. That's for the backend team to troubleshoot and fix. Also, it's a privacy and security concern.
